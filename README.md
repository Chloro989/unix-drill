# UNIX コマンド練習ドリル

[![selftest](https://github.com/chloro989/unix-drill/actions/workflows/test.yml/badge.svg)](https://github.com/chloro989/unix-drill/actions/workflows/test.yml)

ターミナルで動く、日本語の UNIX コマンド練習環境です。
**Python 3 と bash だけで動きます。インストールは不要です。**

打ったコマンドを**その場で自動採点**する練習環境です。
採点は毎回、使い捨てのコピーの中で実行されます。**何をやっても壊れません。**
`rm` を打っても、`>` で上書きしても、次の瞬間には元通りです。

収録しているのは第1〜10章の 102 問（想定 9〜13 時間）と、模擬試験モードです。

## はじめかた

### Google Colab

ノートブック `start.ipynb` を開いて、上から順にセルを実行してください。
インストールは要りません。手で始めたい場合は、セルに次を貼ります。

```python
!cd unix_drill && python3 drill.py setup
```

対話で解くときは、Colab のセルで次を実行します（入力欄が出ます）。

```python
!cd unix_drill && python3 drill.py play 1
```

### macOS のターミナル / Linux

```bash
cd unix_drill
bash setup.sh
python3 drill.py
```

### Windows（WSL または Git Bash）

WSL を推奨します。Ubuntu を開いて、上の macOS と同じ手順です。
Git Bash でも動きますが、一部のコマンドの挙動が本物の Linux と違います。

> **必要なもの**: Python 3.7 以上と bash だけ。
> `pip install` は一切不要です。

## 二つの練習のしかた

### ドリルモード — 問題が出て、その場で採点

```bash
python3 drill.py            # 続きから
python3 drill.py play 2     # 第2章だけ
python3 drill.py review     # 間違えた問題だけ復習
python3 drill.py exam       # 模擬試験（ランダム10問・ヒントなし・最後に採点）
python3 drill.py exam 20    # 問題数を変える
```

模擬試験では、答えを 1 行書いたら次へ進みます。合否はその場では出ません。
全問終えてからまとめて採点し、間違えた問題は模範解答つきで並べて表示します。
紙に書く本番と同じく、実行して確かめられない状態で書ききる練習です。

問題文が出たら、コマンドを打って Enter。すぐに合否が返ります。
入力欄では次の言葉も使えます。

| 入力 | 動き |
|---|---|
| `hint` | 段階的なヒント（1回目=どの道具か / 2回目=オプション / 3回目=答え） |
| `files` | 練習ディレクトリにあるファイルの一覧と行数 |
| `skip` | この問題をとばす |
| `answer` | 模範解答と解説を見る |
| `quit` | 終了（進捗は保存されます） |

### フィールドモード — 本物のシェルで練習する

```bash
bash setup.sh          # playground/ ができる
cd playground
ls                     # タブ補完も履歴も less も本物
cd ..
python3 drill.py show  1-03          # 問題文を見る
python3 drill.py check 1-03 'ls -a notes'   # 答え合わせ
```

`playground/` は好きなだけ壊してかまいません。`bash setup.sh` で作り直せます。
採点は常に手つかずのコピーで行われるので、`playground/` の状態に左右されません。

**ドリルモードで覚え、フィールドモードで身体に入れる。** この順番がおすすめです。

## 題材を切り替える

同じ問題を、別のデータで解き直せます。

```bash
python3 drill.py theme            # 一覧
python3 drill.py theme logs       # サーバーログに切り替え
```

| テーマ | データ | 向いている人 |
|---|---|---|
| `bio` | FASTQ・発現テーブル・BED 風 CSV | 生命科学系（既定） |
| `logs` | アクセスログ・トラフィック集計 | 情報系・エンジニア |
| `general` | 蔵書一覧・日記 | 前提知識なしで始めたい人 |

問題文とコマンドは、テーマに合わせてファイル名が自動で差し替わります。
進捗は共有されるので、「一度解いた問題を別の題材でもう一度」という使い方ができます。

## 採点のしくみ

コマンド文字列を正規表現で照合する方式ではありません。**実際に実行して結果を比べます。**
したがって `wc -l file` でも `cat file | wc -l` でも、正しければ正解になります。

判定は 3 段階です。

1. **静的チェック** — 危険な操作や、解答ファイルの覗き見を実行前に止めます。
2. **出力の比較** — 模範解答を同じ条件で実行し、標準出力を突き合わせます。
   末尾の空白や改行の違いは吸収します。問題によっては行の順序も問いません。
3. **ファイル差分** — `>` で作られたファイルの中身や、`cd` の移動先を比べます。

期待される出力はファイルに書き込まれていません。採点のたびに模範解答を実行して求めます。
データの中身が変わっても、答えが古くなることがない仕組みです。

出力は合っているが、その章で練習したい道具を使っていない場合は「△」が出ます。
これは不正解ではなく、先へ進めます。

`less` のような画面を占有するコマンドは実行できないため、
**紙に書く形式**（試験本番と同じ）の問題として出題し、文字列で照合します。

## macOS と Linux の違いについて

`sed -i`、`grep -P`、`head -20` のように、macOS（BSD 版）と Linux（GNU 版）で
書き方や挙動が違うものがあります。この教材では、

- 差がある書き方は避けるか、
- 問題文に「※」で注意書きを出す

方針を取っています。採点は模範解答をあなたの環境で実行して比べるので、
**どちらの環境でも同じように合否が出ます。**

試験では GNU 版（Linux）の書き方が標準だと考えて答えるのが無難です。

## 問題を自分で足す

`content/problems/*.yaml` に書き足すだけで増えます。判定エンジンは触りません。

```yaml
  - id: 1-11
    title: 例
    prompt: カレントディレクトリの一覧を表示せよ。
    solution: ls
    judge:
      mode: stdout          # stdout / files / both / cwd / text
      normalize: [sort_lines]
    require_any: [ls]       # この道具を使ってほしい（任意）
    hints:
      - どの道具を使うか
      - 必要なオプション
      - ls
    explain: |
      解説。
```

ファイル名は `{table}` `{bigtext}` `{list}` `{log}` `{records}` `{fileA}` `{fileB}`
`{notesdir}` `{notesfile}` `{strings}` のように**役割**で書きます。
列番号や列名も `{namecol}` `{numcol}` `{catcol}` `{agecol}` `{headword}` `{numlabel}`
のように役割で書けば、テーマごとに正しい値へ置換されます。

書き足したら、必ず自己検査を通してください。

```bash
python3 selftest.py
```

全テーマ × 全問題で、模範解答と別解が本当に正解と判定されるかを確かめます。
