# 第3章 三本の管（リダイレクト）

## この章で分かること

すべてのコマンドには、**管が三本**つながっています。

              ┌─────────────┐
    標準入力 →│  コマンド    │→ 標準出力（1番）
     （0番）  │             │→ 標準エラー出力（2番）
              └─────────────┘

- **標準入力 (0)** … 読み込む先。既定はキーボード。
- **標準出力 (1)** … ふつうの結果。既定は画面。
- **標準エラー出力 (2)** … エラーや警告。既定は画面。

出力の 1 番と 2 番は、どちらも既定では画面に出るので、
見た目では区別がつきません。でも**別の管**です。
だから `> file` としてもエラーだけは画面に残る。ここが最初の関門です。

## 記号の一覧

| 記号 | 意味 |
|---|---|
| `> file`   | 標準出力をファイルへ（**上書き**、元の内容は消える） |
| `>> file`  | 標準出力をファイルへ（**追記**） |
| `< file`   | ファイルを標準入力へ流し込む |
| `2> file`  | 標準エラー出力だけをファイルへ |
| `2>/dev/null` | エラーを捨てる |
| `> file 2>&1` | 出力もエラーも同じファイルへ |
| `\|`（パイプ） | **コマンドの出力を次のコマンドの入力へ**（第4章） |

`>` `>>` `<` はコマンドと**ファイル**をつなぐ。
`|` はコマンドと**コマンド**をつなぐ。この対比で覚えるのが近道です。

## つまずきどころ

- `>` の右に大事なファイルを書くと、中身が一瞬で消える。復元できない。
- `wc -l file` と `wc -l < file` は出力が違う。後者はファイル名を表示しない
  （`wc` がファイル名を知らないから）。この違いは理屈で説明できると強い。
- `;` は「順に実行」、`&&` は「成功したら実行」。
