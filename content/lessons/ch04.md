# 第4章 パイプでつなぐ

## この章で分かること

前章では、コマンドの出口を**ファイル**へ向けました（`>`）。
この章では、出口を**次のコマンドの入口**へ向けます（`|`）。

    コマンドA ──┐
                │  出口 → 入口
                └──> コマンドB ──> 画面

これが `|`（パイプ）です。途中にファイルは作られません。
水道管を直結するイメージで、データは流れながら加工されていきます。

    ┌────────────┬────────────┬────────────┐
    │  cat file  │  head -n 12│  tail -n 4 │ → 画面
    └────────────┴────────────┴────────────┘

## なぜこれが強いのか

UNIX の道具はどれも「行の並んだテキストを受け取り、行の並んだテキストを出す」
という同じ形をしています。だから**どれとどれでも自由につなげます**。

小さな道具を組み合わせて、その場で必要なものを作る。
これが UNIX の設計思想で、試験でも実務でも問われるのはここです。

## 組み立てかたのコツ

長いパイプラインをいきなり書こうとしないこと。**1 段ずつ足して確かめます。**

```bash
head -n 20 file                     # まず 1 段
head -n 20 file | tail -n 3         # 確かめてから 2 段目
head -n 20 file | tail -n 3 | wc -l # さらに足す
```

## つまずきどころ

- `A > B` と書くと、B は**ファイル**になる。コマンドをつなぐのは `|` だけ。
- `cat file | wc -l` は動くが、`wc -l file` で足りる。cat を挟む必要はない
  （useless use of cat と呼ばれます）。ただし練習では流れが見えて分かりやすい。
- `head` と `tail` は順番で結果が変わる。どちらを先に置くかを意識する。
